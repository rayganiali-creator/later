# Architecture — بعداً (Later)

**Stack:** Flutter 3.47 / Dart 3.13 (UI + logic), Kotlin (share sheet, widgets, shortcuts, icon aliases, Bazaar billing bridge), SQLite (`sqflite`), Android Keystore (`flutter_secure_storage`), `flutter_local_notifications` (AlarmManager).
Flutter was chosen because the product is UI-heavy (RTL, Jalali calendar, animation), needs one code base with real native hooks, and all the required Android features have mature plugins or a thin Kotlin layer.

## Layers (lib/)
| Path | Responsibility |
|---|---|
| `core/config` | `AppConfig` (limits, versions, flavor gate), `ProPlans` (prices/durations — **single place to change prices**) |
| `core/util`, `core/theme` | dates (Jalali/Gregorian), Persian text helpers, URL sanitizing, ids, theme |
| `domain/` | Pure Dart, no I/O: models, filters/sort/search, Smart Pick, snooze rules, stale rule, reminder planner, transitions, Pro entitlement maths, exporters |
| `data/` | SQLite (`db/app_database.dart`, migrations), `repository.dart`, backup codec (`backup/`), Pro service (`pro/`), `controller.dart` (single source of truth for the UI) |
| `services/` | Interfaces + Android implementations: notifications, platform bridge (MethodChannel), purchases, file picker, background notification actions |
| `ui/` | Screens, sheets, widgets. `AppScope` (InheritedNotifier) exposes the controller |
| `l10n/` | ARB → `AppL10n` (fa complete, en complete). Generated by `flutter gen-l10n`; source table: `tool/gen_arb.py` |

Every platform dependency sits behind an interface (`NotificationGateway`, `PlatformBridge`, `PurchaseGateway`, `FileGateway`, `Vault`) so tests run on the host with fakes.

## Database
`later.db`, schema version `AppConfig.dbSchemaVersion` (=1). Tables: `items`, `categories`, `events` (history/statistics, survives item deletion), `settings` (key/value). Migrations: `AppDatabase._migrations[oldVersion]` runs inside the upgrade transaction; opening a *newer* DB than the app supports throws instead of corrupting it. Pro entitlement is **not** in this DB (see Security).

## Key rules
* 1 month = 30 days, 3 = 90, 6 = 180 (exact, timezone-independent, UTC epoch).
* `newExpiry = now + max(currentExpiry − now, 0) + purchasedDuration`.
* Pro is derived (`expiresAt > effectiveNow`), never stored as a boolean. `effectiveNow = max(clock, lastSeen)` blocks clock rollback.
* When Pro ends nothing is deleted; Pro features are gated at read time (recurrence ignored, extra categories kept but read-only for creation, accent falls back, history window shrinks).

## Notification architecture
`ReminderPlanner` (pure) → list of `PlannedReminder` (next fire time per item; repeat rolled forward; capped at 300 soonest). `ReminderService.sync` = `cancelAll()` + schedule each → idempotent, so duplicates are impossible by construction. Sync runs on: app start, every resume (timezone/clock changes, alarms cleared by the OS), every item/settings change (debounced 400 ms), restore, Pro change.
* Stable notification id = FNV-1a(itemId).
* Recurrence uses `matchDateTimeComponents` (time / dayOfWeekAndTime / dayOfMonthAndTime) so repeats keep firing without the app.
* Boot / app update: the plugin's `ScheduledNotificationBootReceiver` re-registers stored alarms; the next launch re-syncs anyway.
* Exact alarms are optional (`SCHEDULE_EXACT_ALARM`); without them reminders are inexact-but-allow-while-idle.
* Notification buttons (Done / Tomorrow) run in a background isolate (`services/background_actions.dart`) using the same `Transitions` as the UI.
* Permission (`POST_NOTIFICATIONS`) is requested only when the user first turns on a reminder.
* Limits (documented, cannot be engineered away): force-stop clears alarms until the app is opened again; some OEMs kill background work; Doze can delay inexact alarms; DST/timezone changes are re-applied on the next app launch.

## Backup architecture
`.later` = UTF-8 JSON `{format, schemaVersion, appVersion, createdAt, checksum(SHA-256 of data), data{items,categories,events,settings,pro?}}`.
Decode pipeline: size cap (64 MB) → nesting-depth guard → JSON parse → format/version checks (future → refuse) → checksum → **migrate** (`BackupMigrator`, chain v→v+1) → strict validation & sanitizing (ids `[A-Za-z0-9_-]{1,64}`, enums, timestamps, length clamps, http(s)-only URLs, duplicate ids rejected) → replace-all in **one SQLite transaction**. A safety copy of the current data is written to private storage first. Pro entitlement inside a backup is HMAC-signed with `LATER_PRO_SIGNING_KEY` (build-time define); without a key nothing is exported/imported.

## Widgets, quick actions, share
Dart pushes a snapshot (count, suggestion, top items, localized strings, pro flag) → `WidgetStore` (SharedPreferences) → `LaterWidgetProvider` (small, free) and `LaterListWidgetProvider` (list, Pro). Buttons fire explicit intents into `MainActivity` (`app.baadan.later.QUICK`). Dynamic launcher shortcuts: Add / Pick / Search. Share sheet: `ACTION_SEND text/plain` + `PROCESS_TEXT`; content is length-limited and cleared from the intent after capture.

## Flavors
`store` (market, no test tools) and `qa` (`.qa` suffix, test tools on). `AppConfig.testToolsEnabled` = `appFlavor == 'qa' || kDebugMode`; store flavor is hard-off.
